# Тестовое задание: REST API для заметок (Go + net/http + pgx)

## Цель

Познакомиться с базовым использованием `net/http` (HTTP-сервер и роутинг) и `pgx` (работа с PostgreSQL) на простом примере — без фреймворков, без ORM, только стандартная библиотека и драйвер БД.

## Что нужно сделать

Реализовать простой HTTP API для хранения заметок (`notes`) с CRUD-операциями (Create, Read, Update, Delete), сохраняя данные в PostgreSQL через `pgx`.

## Структура данных

Таблица `notes`:

| Поле       | Тип       | Описание                  |
|------------|-----------|----------------------------|
| id         | SERIAL    | Первичный ключ             |
| title      | TEXT      | Заголовок заметки          |
| content    | TEXT      | Текст заметки              |
| created_at | TIMESTAMP | Дата создания (по умолчанию `now()`) |

## Эндпоинты

| Метод  | Путь           | Описание                          |
|--------|----------------|-------------------------------------|
| POST   | `/notes`       | Создать заметку                    |
| GET    | `/notes`       | Получить список всех заметок       |
| GET    | `/notes/{id}`  | Получить одну заметку по id        |
| PUT    | `/notes/{id}`  | Обновить заметку по id             |
| DELETE | `/notes/{id}`  | Удалить заметку по id              |

### Формат запросов/ответов

Все данные передаются в формате JSON.

**POST /notes** — тело запроса:
```json
{
  "title": "Купить молоко",
  "content": "Не забыть зайти в магазин по дороге домой"
}
```

**Ответ (201 Created)**:
```json
{
  "id": 1,
  "title": "Купить молоко",
  "content": "Не забыть зайти в магазин по дороге домой",
  "created_at": "2026-08-11T10:00:00Z"
}
```

**GET /notes** — ответ (200 OK):
```json
[
  {
    "id": 1,
    "title": "Купить молоко",
    "content": "Не забыть зайти в магазин по дороге домой",
    "created_at": "2026-08-11T10:00:00Z"
  }
]
```

**GET /notes/{id}** — 200 OK с одной заметкой, либо 404 Not Found, если заметки с таким id нет.

**PUT /notes/{id}** — тело запроса такое же, как у POST (title, content). Ответ — обновлённая заметка, либо 404, если id не найден.

**DELETE /notes/{id}** — 204 No Content при успехе, либо 404, если id не найден.

## Требования к реализации

1. **Роутинг** — используйте `net/http` (стандартный `http.ServeMux`, Go 1.22+, с поддержкой методов и параметров пути вроде `"GET /notes/{id}"`). Сторонние роутеры (chi, gorilla/mux) использовать не нужно — цель именно познакомиться со стандартной библиотекой.
2. **Работа с БД** — используйте `github.com/jackc/pgx/v5` (можно `pgxpool` для пула соединений, но для этого элементарного задания допустим и одиночный `pgx.Connect`).
3. **Все SQL-запросы должны быть параметризованными** (`$1, $2, ...`) — никакой конкатенации строк с пользовательским вводом.
4. **Обработка ошибок**:
   - невалидный JSON в теле запроса → `400 Bad Request`;
   - заметка с указанным id не найдена → `404 Not Found`;
   - ошибка на стороне БД → `500 Internal Server Error` (плюс лог ошибки в консоль сервера).
5. **Код должен компилироваться и запускаться** через `go run main.go` (можно разбить на несколько файлов, если хочется, но для этого простого задания один файл — это нормально).
6. Таблицу можно создавать вручную заранее, либо автоматически при старте сервера через `CREATE TABLE IF NOT EXISTS`.

## Подключение к БД

Строку подключения можно захардкодить или брать из переменной окружения — как удобнее, для этого простого задания жёстких требований по конфигурации нет.

Пример:
```
postgres://postgres:1234@localhost:5432/postgres
```

Поднять PostgreSQL локально можно через Docker:
```bash
docker run --name pg-test -e POSTGRES_PASSWORD=1234 -p 5432:5432 -d postgres
```

## Как запустить и проверить

```bash
go run main.go
```

Проверить работу можно через `curl`:
```bash
curl -X POST localhost:8080/notes -d '{"title":"тест","content":"привет"}'
curl localhost:8080/notes
curl localhost:8080/notes/1
curl -X DELETE localhost:8080/notes/1
```

## Что не нужно делать

- Не нужна авторизация/аутентификация.
- Не нужны миграции через отдельные инструменты (goose, migrate и т.д.) — достаточно `CREATE TABLE IF NOT EXISTS`.
- Не нужны тесты (хотя это плюс, если решите написать) — задание элементарное, цель — прощупать оба модуля руками.

## Полезно вспомнить перед началом

- `net/http`: `http.ServeMux`, `r.PathValue("id")` для извлечения параметра пути (Go 1.22+), `w.Header().Set("Content-Type", "application/json")`, `json.NewEncoder(w).Encode(...)`, `json.NewDecoder(r.Body).Decode(&v)`.
- `pgx`: `pgx.Connect`, `conn.Exec` (для INSERT/UPDATE/DELETE), `conn.QueryRow` (для одной строки), `conn.Query` + `rows.Next()` + `rows.Scan()` (для списка строк), обязательная передача `context.Context` первым аргументом.
